"It is a truth universally acknowledged, that a pipeline in possession of good data must be in want of a manifest."
What follows is the empirical accounting of our system — measured across S3 and Azure Blob Storage, three dataset sizes, and 329 benchmark runs in total.
FINDING THE FIRST
Publishing Overhead
Validation and manifest write, set against the cost of upload itself (S3, all sizes)
Total publish overhead: 2.7% – 4.8% of upload time. Validation dominates; manifest writes remain consistently under one second. A small price for atomic visibility and rollback.
FINDING THE SECOND
Transfer Throughput
S3 vs Azure, after tuning the Azure SDK to match S3's chunking defaults
Azure's tuned upload exceeds S3 at size M (46 vs 32 MB/s), but S3 maintains a consistent download advantage across all sizes.
FINDING THE THIRD
The Warm-Up Effect
S3 upload latency by run number — first impressions are slower
Initial runs incur higher latency from connection setup. For size L, run 1 takes ~370s vs ~300s on subsequent runs. Always benchmark with warm-up runs discarded.
FINDING THE FOURTH
Selectivity vs Scan Time
Seven query presets on S3 (size M), filter selectivity vs scan duration
A 100-fold difference in selectivity produces only modest changes in scan time. Predicate pushdown is ineffective because the data is uniformly distributed across row groups. The remedy: partition by frequently filtered columns.
FINDING THE FIFTH
Scan Performance: S3 vs Azure
Preset v1 (region filter), all three dataset sizes
For size M, Azure is 3–4× slower than S3 (608s vs 188s). PyArrow's native S3 adapter outperforms adlfs at scale, especially for I/O-bound analytical workloads.
RECOMMENDATIONS
Three Practical Resolutions
drawn from the evidence above
I. Use manifests. A 3–5% overhead buys atomic visibility, rollback, and safe concurrent reads. The default for production.
II. Partition the data. Partition by date or region. Without it, predicate pushdown cannot prune row groups, regardless of how selective the filter.
III. Mind the SDK. For PyArrow analytical workloads, S3's native filesystem outperforms adlfs. Always tune chunking and concurrency.

Publishing Overhead

Validation and manifest writing add only milliseconds to a publish operation — a negligible cost compared to the upload itself, which takes seconds to minutes. The manifest is essentially free.

Upload vs Publish Overhead

In context: the publish overhead is barely visible next to the upload itself. Manifest-based publishing adds a thin sliver of time to operations that already take seconds to minutes. You get atomic safety essentially for free.

Transfer Throughput: S3 vs Azure

Without SDK chunking, Azure collapses on the largest dataset. With chunking enabled (see next chart), Azure recovers to comparable levels. SDK defaults matter.

Azure SDK: Chunking Impact

Azure's upload_blob() with default settings sends one block at a time. Enabling chunked concurrent uploads gives a 6× speedup on Large datasets (1322s → 220s) — the single biggest performance lever in the project.

Scan Time Scaling

Scan time grows roughly linearly with dataset size, regardless of which query preset is used. Data volume dominates query latency — the filter you apply matters far less than how much data sits underneath.

Scan Selectivity (Predicate Pushdown)

Scan time does not always shrink with row selectivity. Queries that match few rows can still pay the full file-listing and metadata cost, while queries matching many rows benefit from streaming reads. Predicate pushdown matters most when filter columns align with parquet's row-group statistics.
